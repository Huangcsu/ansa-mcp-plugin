# 复杂几何实体网格的复用流程

本页将既有复杂几何试验中的有效做法固化为当前 MCP 的使用流程。目标是降低反复试切、重复生成接口和失败后整模重做的成本。S25 仅保留为回归证据，不以修补该模型作为工具开发的前提。i10、i02 的历史正例只覆盖边分段或局部源面；2026-10-26 的整件模板诊断中，i10、i02、i23 均未满足矩形多块模板，不能作为整件自动实体网格通过案例。i08 的点投影或范围失败继续保留。

完整链路分为“对称性检查与处理范围选择 → 原始 CAD 边界映射 → 原生 CONS 分段 → 源面网格 → 实体网格 → 目标 CAD 与整件验收”。每一段都要单独核对；前一段成功不能推出后一段完成。原始 FACE/CONS 映射、等分段组和共享边归属由调用方显式提供，工具不会按近似坐标自动合并。

## 第一步：检查几何对称性

在清理、切分或设计网格前，先检查镜面对称、旋转/周期对称及轴对称或回转特征。只读核对候选对称面、旋转轴、最小周期角、重复份数和对应的外形、孔道、厚度及局部特征，记录证据、容差、代表域和不确定项；包围盒或画面相似只用于提出候选，局部圆孔不证明整件回转对称。材料、连接及已知工程条件的对称性另行说明，不能从几何对称推导半模型或周期模型求解条件。

已确认对称且任务允许时，先备份整件并删除另一半，完成保留半的关键块组、连续网格和质量验证后再镜像；镜像后核对对称面节点、完整面连接、单元方向、重复及保存重开。未确认时保留整件。这是使用流程要求，不是已注册的自动对称识别或自动删半能力。

已确认旋转/周期对称时，任务允许则先划分最小重复扇区，明确两侧周期边界节点/单元面的对应，再旋转复制并核验每一处交界。连续轴对称、有限旋转周期和镜面对称分别判断；组合使用时记录各步变换与代表域，不凭局部特征扩大复用范围。

同时核对多面对称：两个在整件上共同成立的正交镜面可用1/4代表域，三个正交面可用1/8；完成代表域后按记录的顺序镜像，并核对交线及各接口，避免重复节点/单元。非正交镜面与镜面、旋转周期的组合须另行核实实际重复关系，不能简单按面数折半。

## 先读取显式几何特征

工作源码新增只读 `ansa_geometry_features`，用于读取调用方选定的 CAD 特征。FACE 通过显式 FACE→CONS 拓扑和 `SurfaceInfo` 报告局部曲率；只有显式选择的 CURVE 100/110 才用于种子建议，且先从有界 IGES 解析直线或圆弧，再用 ANSA 原生长度交叉核验。它不拟合任意曲线、不自动识别孔、不自动分块或切分。

原生 CONS 闭环读取已接入同一工具：依据 HOT POINT 的实际编号、坐标和双向邻接构建有序环，检测开口、分叉、重复、缺失及坐标冲突。闭环完整与解析几何完整分别报告；CONS 环仅确认连通，不自动判定圆孔，也不使用近似卡片长度生成圆弧种子。此证据用于在分块前筛出无法直接映射的边界，减少反复试划；真正的环形区尺寸和解析圆弧归属仍需后续能力确认。

每次缓存访问或读取新特征证据页，都会重新导出并校验请求范围的 CAD 指纹和 FACE→CONS 拓扑。派生缓存最多 8 项、4 MiB；命中仍需范围导出，只跳过 `SurfaceInfo` 查询和每条 CURVE 的单独导出。指纹受导出精度限制，范围外几何不校验；证据 `usable_for_mutation=false`。初版限 NASTRAN 毫米单位、实体已有 Part 且当前数据库已保存；导出失败不会自动保存或重开。当前没有端到端自动化，也不报告未经同模型实测的加速幅度。完整参数示例和 schema 见[结构化网格契约](structured-meshing.md#显式-cad-特征读取)。

## 先按特征制定分块策略

| 特征 | 建议分块与生成方式 | 工具中的对应约束 |
| --- | --- | --- |
| 等截面直线体、平板或直筋 | 划成横截面清晰的块，四边形源面一次直线扫掠 | `geometry_features` 可读取显式 FACE/直线；`mesh_source_audit`；多个已就绪块用 `mesh_sweep_prepare` 合批 |
| 圆孔、凸台、圆环 | 优先环形分区或 O-grid 思路，统一周向分段，单独控制径向与轴向分段 | 显式选择已知圆弧交给 `geometry_features`，再结合 `mesh_seed_plan` 的弦误差、等分组及 `multiple`；不会自动识别孔，环形 CAD/源面布局仍需显式建立 |
| 筋板交叉、分叉和根部过渡 | 先形成闭合过渡区，再围绕它安排易扫掠块；不要最后留下无法填充的尖薄空腔 | `geometry_partition_plan/apply` 小步切分；块依赖由 `mesh_block_plan` 表达 |
| 变截面、扭转或弯曲区 | 另做局部块与源/目标对应设计；允许有限三角源面过渡生成 CPENTA | 现有直线扫掠不覆盖任意变截面；`max_penta_fraction` 控制明确计划中的比例 |

复杂连接处先设计过渡拓扑，再确定外侧规则块。四边形源面优先；三角源面用于明确的局部过渡，不能把所有困难区域都改成自由三角面后宣布结构化完成。

## 关联块组执行规则

本节规定调用原生工具前的工程决策和失败后的转向方式，不新增自动分块或返工入口。具体案例的执行计划、试验和模型继续放在被Git忽略的过程目录；历史正例不能替代新块组的适用性判断。

### 先按网格流向设计

切分或实体填充前，先给出一张简明块组图或下列表格。方向和分段尚未确定的块保留为待设计；可只读调查或用有明确假设的有界粗网格试验补充证据。

| 计划项 | 需要明确的内容 |
| --- | --- |
| 几何与块组 | 孔轴、板厚、圆角/相切处；本轮完整关联范围及外部邻域 |
| 映射方向 | 每块的源面组、目标面组、侧面组、扫掠方向及其选择理由；caps可以包含多个FACE |
| 分段对应 | 共享边链的整数分段、相对边对应、厚度层数；逐一检查同一接口在两侧的角色 |
| 可行性风险 | 尖薄余域、退化端盖、相切点、方向转换；所用原生方法及失败时返回哪一级设计 |
| 边界与返工 | 工程硬约束、暂时稳定的组外边界、允许重做的探索网格，以及需要连带重生成的邻域 |
| 本轮判据 | 最小验证块组、预期结果、必要验收、失败后的具体转向 |

闭合、正的域体积或 `Ready to Mesh` 不足以证明整个块组能同时映射。优先用适度粗网格验证决定整体布局可行性的难交接块组，再扩展外侧规则域；细化尺寸和移动节点不能代替不合理的分块或流向设计。

### 协调接口后冻结，按受影响块组返工

- 原始外形、孔道、材料和用户明确指定的边界属于工程硬约束。人工切面、caps、分段及探索阶段生成的网格属于可重新设计的选择；先前检查通过表示该检查点有效，不自动成为永久禁止修改的条件。
- 当前施工带的共享面须先协调两侧网格流向、分段和层数，再冻结。Freeze会锁定面和边界CONS；核对实际 `Frozen` 状态及共享边邻接，不仅观察所选面，也不把全部解冻当作默认解法。
- 接口需要调整时，先列出会失配的面网格、实体和邻域，将其纳入新的明确执行范围。保留组外稳定边界，保存备份，撤回受影响实体后协调源/目标面及分段，重新生成完整块组，再核对实际单元面的匹配、质量和范围外保持。
- 需要扩入相邻已划域时，先更新块组范围和前置条件；在已有授权内继续执行，无需仅因“之前通过过检查”而再次索要许可。涉及用户禁止修改的工程条件时才提出具体冲突。
- 返工不得绕过现有MCP工具的硬性契约，也不得删除保护断言或放宽判据来通过旧计划。工具范围不适用时，依据同版本原生能力另组有界操作。拓扑改变后重新绑定实体，不重放旧ID、计划哈希或操作键。

### 按失败机制决定下一步

每次新尝试记录：基线和范围、缺陷位置/类型、受限边界与可移动节点、原因假设、拟改变的条件、预期现象、实际结果和下一步决定。只保留支撑决定的证据，不为每个字段新增独立验收轮次。

| 观察到的失败 | 优先诊断及下一步 |
| --- | --- |
| 开口、缺面、尖薄余域或源/目标不对应 | 返回几何分块、完整边链及caps设计，先确认可行方向 |
| 共享边分段/层数冲突，或冻结面妨碍相邻域 | 重新协调关联块组，按明确范围连带返工；不只重划单侧面 |
| 少量内部坏单元，存在可移动节点且边界布局合理 | 在有位移约束的局部范围做一次针对性原生质量调整 |
| 坏单元受边界控制、没有足够可移动节点，或同类缺陷重复 | 返回源面布局、接口或分块设计，不继续依次尝试平滑、拆分和更换生成器 |
| 参数/实体类型错误、序列化错误或API版本差异 | 单独核对契约，以最小探针确认；不归类为网格算法失败 |
| 超时、未确认或未知写入 | 查询原任务和台账并独立回读，按实际状态恢复；不换键重放 |

同一几何及接口约束下，同类缺陷在**首次尝试加一次针对性调整**后仍重复、且没有支持新假设的证据时，结束该分支并返回上一层设计。这是停止无效分支的条件，不是停止整个任务。换工具名、参数或操作键不能重置判断；重新尝试须记录实质前提变化。判据不因失败而自动放宽。

### 方案判断与局部质量

块组计划必须分别说明布局判断和数值检查，沿用项目已约定的范围与准则，不在实施末期临时追加工程门槛。

| 判断阶段 | 需要回答的问题 | 最小证据 |
| --- | --- | --- |
| 面网格方案 | 孔道是否保持，圆周分段是否满足已约定的几何精度，厚度层数、尺寸过渡和方向是否适合接续 | 明确的分段/层数选择及理由；无遮挡局部图，复杂交接处按需补一张剖面 |
| 局部实体质量 | 实际单元类型、方向、正体积和既定指标是否通过，缺陷由哪些边界或节点控制 | 受影响范围的原生质量读数、实际连接和缺陷定位；未知读数保持未知 |
| 块组与整体完成度 | 邻域是否完整共面相接，是否仍有空域/断开的实体部分，几何及孔道是否覆盖 | 块组完整单元面核对及已有几何证据；未完成模型明确保留未完成状态 |

“允许少量四面体”须落实为明确的候选过渡区域和使用理由。分别统计HEXA、PENTA、PYRAMID、TETRA数量；数量占比的分母是同一已统计实体范围。体积占比只能用同范围、完整且一致的体积证据计算，缺失时记录未知；不得把实体数比例写成体积比例，也不得从局部阶段推断最终整件比例。没有项目约定时，不擅自把“少量”改为一个固定百分比或临时求解器标准。

质量指标通过、布局已审阅和整件完成分别记录。保持原有效数值证据，未审阅的布局项标为待定；不能因新增记录字段而重跑未变化的真实网格。

### 视频案例的决策过程

封面和少量概览帧用于找相似几何；进入具体瓶颈后，围绕一段决策连续复核操作前、选择对象、操作及操作后的拓扑。根据需要按事件补帧、查看原分辨率或读取可用讲解；连续片段信息未取得时，明确缺口，不用更多离散截图替代未知步骤。

逐步标明操作层级：实体修剪、曲面拓扑、面网格或体网格。记录实际选择的轮廓、面或实体、修剪延伸方式及前后变化，先复现孔周与交接区的面片流向和对应边链分段。不能把每条曲面分区线都解释成独立体块，不能把面网格中的边分段数或行数解释成实体厚度层数，也不能仅凭绿色显示宣称体网格已完成。三维源面、目标面和层数没有读清时保留未知，不能用熟悉的扫掠方式替作者补全步骤。

每张经验卡至少包含：适用几何和不适用条件、局部瓶颈、切分理由、源/目标/侧面角色、共享边分段和冻结变化、失败及转向、ANSA候选原生步骤、来源时间段与证据类型、尚未验证的条件。作者解释、画面观察、分析推断、未知分别标注。一个方法只保留一份正文，多视频增加来源或边界；后续优先返回简短决策摘要，再按缺口加载原证据。

经验迁移先验证一个包含必要邻接约束的最小块组。图形相似或原生API名称对应不足以直接重放实体编号、参数和操作次序。蒸馏素材、经验草稿和案例过程文件保存在被Git忽略的过程目录，不随通用规则纳入项目版本管理。

### 可复用执行与显式设置

沿用现有任务/Journal、备份、范围保护和网格上下文，将案例代码限制为范围、caps、分段、单元类型和必要诊断。模型代次或拓扑变化后重新绑定；离线检查能发现的结果类型与序列化问题先离线处理，陌生原生行为用一个独立小探针集中确认。

内部 `meshing_context.run_with_context` 接受显式 `element_type="Quad" | "Mixed" | "Tria"`。默认Quad兼容既有映射调用；混合过渡域须在计划中选择并传入相应类型。上下文在调用回调前读取原生设置确认所选类型，成功或失败后恢复原配置；该参数不会自动重划网格，也不改变公开工具的支持范围。恢复当前ANSA会话时须核对实际加载的实现，源码修改不等于已安装或已在旧进程中生效。

同一个块组中使用同一配置的相关原生步骤，可由一个有界回调串行组织，期间保留范围和关键前提检查。需要切换配置或扩大范围时重新规划；不能为了减少往返而绕过工具要求的备份、前置条件和未知任务查询。

### 验证粒度与进度记录

| 阶段 | 记录或检查 | 停止条件 |
| --- | --- | --- |
| 执行前 | 当前绑定、基线、范围、原因假设、原生配置及备份 | 前提不成立则先处理前提 |
| 试划/调整 | 关键边界及受影响局部结果 | 已证明失败的分支按诊断表转向，避免继续做最终验收 |
| 块组接受 | 实际单元面、既定局部质量、范围保持和必要保存重开 | 最小验收通过即停止追加检查 |
| 后续复用 | 核对证据相关的连接、坐标、准则及范围 | 仅重查被实际变更影响的结论 |

内部上下文返回 `timings_ms`，分别记录配置捕获、临时设置、回调、恢复及总耗时。它衡量上下文内部阶段；回调可能包含多个操作，不等同于纯网格生成时间，恢复耗时包含必要回读。它也不包括外部MCP排队、传输、人工阅读或模型推理时间，不能据此宣称端到端加速。未执行阶段保持未知/未执行状态，耗时不参与工程验收或计划指纹。

每个案例只保留一个当前状态入口，指向有效模型、证据、下一计划和暂停状态；历史报告注明对应检查点。进度摘要优先列出关键接口已解决/未解决项、仍缺区域、完整单元面连通部分、方案审阅与质量证据状态，再给单元类型和阶段数量。不得按“已划域数/总域数”换算整体完成百分比，或用成功调用数代替工程进展。

## 工具调用顺序

1. **建立基线和保护约束。** 读取当前实例、模型代次、deck、单位和完整几何范围，确认当前数据库已保存并保存检查点；明确孔、配合面、主要尺寸及允许简化的区域。
2. **读取显式特征。** 仅在 NASTRAN 毫米单位且实体已有 Part 时，对已知 FACE/curve ID 调用 `ansa_geometry_features`。核对范围、拓扑、曲率或原生长度证据；导出失败时先处理数据库状态，不期待工具自动保存或重开。
3. **按块组计划显式分区。** 先完成上述网格流向、接口角色及分段对应设计，优先验证根部和过渡区。`ansa_geometry_partition_plan` 预览明确切面，`ansa_geometry_partition_apply` 按新鲜计划和备份执行一次切分，核对实际变化。原生 ID 变化必须更新对应关系。
4. **显式映射并统一整数分段。** 先建立原始 CAD 边、FACE、CONS、共享边组和等分段组的显式对应表。尺寸与曲率建议仍由 `ansa_mesh_seed_plan` 根据调用方声明的长度、半径、目标长度和容差计算；完整返回的 `seed_constraints` 交给 `ansa_mesh_block_plan`，结合块依赖检查。欠定、冲突或超预算不能当作可执行计划。
5. **读取并首次写入原生 CONS 分段。** 对准备写入的同一 FACE/CONS 集合调用 `ansa_mesh_seed_read`，核对卡片点数、HOT POINT、邻接和 `seed_snapshot_sha256`；再用该哈希和绝对新建备份路径调用 `ansa_mesh_seed_apply`。写入按相同段数分组，只有写后边数、全部边界点投影、CAD 哈希和非目标 FE 均通过时才算本阶段完成。该入口面向原始 CAD 首次分段；目标 CONS 已有内部 GRID 且请求改变边数时，会在 `NumberPerimeters` 前拒绝，需另行取得可审计的复用契约。原生 CONS 卡片长度仍是近似值，不能自动当精确圆弧。
6. **协调并共用源面。** 在同一接口上保留相同 GRID 身份与整数分段。CONS 分段与源面网格是两个阶段；写入 CONS 后仍须显式生成对应源面，并检查面片覆盖、共形和共享节点。两侧角色、分段及层数协调后再冻结；需要调整已划接口时走上述块组返工流程。扫掠轴向 `steps` 与边的分段数继续分开管理。
7. **联合预检和合批。** 将源网格已存在、依赖已满足的块交给 `ansa_mesh_sweep_prepare`。一次回读源面合集，检查粗边内部的悬挂节点和非流形边；先形成共享 GRID 的不可拆组件，再按预算合并兼容的同平面组件。共享组件不能同次扫掠时，整体阻止返回执行参数。
8. **按组执行和检查。** 从证据分页读取 `groups` 中的 `sweep_params`，为每组补充当前绑定、唯一 `operation_id` 和新备份路径，调用 `ansa_mesh_sweep`。执行器仍独立重读来源和范围、验证新实体及来源映射。多组按顺序执行；首个失败或未知结果停止后续组，查询原任务与台账，不换键重放。
9. **验收目标 CAD 和整件网格。** 分别检查目标端盖（cap）、侧壁（sidewall）、共享接口、面片内部偏差、质量、实体交叠及保存重开。目标网格必须回落到相应原生 CAD 面；只把源面沿方向拉伸、或仅让少量边界节点位于 FACE 上，不能称为贴合原 CAD。SaveAs 后检查当前数据库名；需要切换基线时显式重开已保存文件，再更新模型上下文。

当前已具备显式 CONS 首次分段、保留种子的四边源面、有限六面 CAD Map、原生 MapBlock 准备，以及矩形多块的增量/合批填充。任意 CAD 自动最优分块、自动 O-grid 和未知曲面域仍未开放。只读 T1/T2 候选不具有写权限，真正的准备和填充每次都独立重读当前模型。

播种保持已通过 `ansa_mesh_surface(method="mapped_existing_seeds")` 复用原生 `Create4SidedMesh` 落地，显式禁止重设间距和三角拆分，核对 CONS→CQUAD4 的格点、连接及所属 FACE。旧长度模式仍独立；不能用旧 QUAD 分支替代保留种子的入口，也不自动切换 deck。几何与网格核心按求解器无关方式复用；本任务不另行开展跨deck专项或求解器工程验收，必要卡片读写差异由底层适配处理。

## 分段与网格完成的判断分界

- `ansa_mesh_seed_read` 只读取原生 CONS 卡片分段、HOT POINT 和几何/拓扑哈希；`points`、`point_count` 为 `null`，`expected_point_count` 只是推算值。读取、分页和写前预检不调用 `CollectEntities(CONS, GRID)`。
- `ansa_mesh_seed_apply` 在确认新备份和上下文后，才显式收集全部 CONS 的虚拟点引用。原生新增 virtual ref 会进入 `__ALL_ENTITIES__`，备份后保护只接受“相对备份前新增且在 CONS perimeter 集合内”的 GRID，并把新增 ID 单独列出。所有原有 GRID 继续冻结，包括已有 perimeter 内点、端点和 solver GRID；写后还要核验目标边数、全部边界点投影、全 CAD 哈希、非目标 FE 和允许变化的卡片字段。
- 当前尚未核实 ANSA 2026.1.0 存在可可靠区分操作前已有 virtual ref 与 solver GRID 的同版本接口；不能据此声称 ANSA 本身不支持。目标 CONS 若在操作开始前已有内部 GRID，且请求改变分段数，会在 `NumberPerimeters` 前拒绝。该工具只承诺受控的原始 CAD 首次分段，不承诺复用或改写已有 perimeter 内点；该能力需要另行核实并验证复用契约。拒绝前备份和虚拟点物化可能已发生，仍须查询原任务与 `possible_effects`。
- 潜在点预算使用操作前 `budget_base` 的 entities/GRID 基数。首次 `CONS→GRID` 前按全 CONS 的 first-order 卡片 `Num. of Nodes+2` 累计；写前 preflight 另按 `max(当前内部点数+2, 请求 segments+1)` 重算，并检查基数加潜在点数不超过 entities 10000、GRID 20000。最终 materialized readback 复用同一 `budget_base`，另独立检查实际 entities/GRID 上限，不把已物化节点再加一遍。共享端点和已有 perimeter ref 仍会进入潜在点数，因此可能保守拒绝。
- 受限真机 i10、i02、i23 各三条原始边的分段与保存重开通过。i02 中 CAD canonical hash 完全不变；目标 CONS `BoundBox` 的变化约 `2.14e-8 mm`，真正邻接 FACE 的 bounds 和这些 FACE 所属 Part 的包围盒极值、尺寸和对角线等派生值约 `5e-13`。`_audit` 只对这些目标/真实邻接派生 bounds 和对应 Part 边界字段接受不超过 `1e-7 mm` 的变化；额外 `face_ids` 所属 Part 不获得豁免。CAD hash 必须完全相等，raw 变更前后 SHA-256 仍保存在 `tessellation_changes`。该容差不是工程质量容差，也仍未证明连续 CAD 等价。
- i08 的原 CAD canonical hash 虽未变化，但点投影误差或范围检查失败，结果保留 `recovery_required` 并计入失败；没有放宽投影精度或范围门禁。
- CONS 分段成功不自动生成源面网格，更不生成整件体网格。源面和实体仍分别需要覆盖、共形、质量和交叠检查。
- 后续扫掠/模板必须验证 target CAD 的端盖与侧壁。端盖、侧壁、共享接口和孔壁应分别建立显式归属；任意拉伸只能提供候选体，不能凭单元数量或少量节点投影宣称贴合原 CAD。

## 尺寸与曲率种子示例

`ansa_mesh_seed_plan` 的局部参数示例（还须带通用绑定与操作字段）：

```json
{
  "deck": 1,
  "plan": {
    "edges": [
      {"id": "hole-quarter", "kind": "circular_arc", "length": 4.71238898038469,
       "radius": 3.0, "max_chord_error": 0.02, "target_length": 1.0, "multiple": 2},
      {"id": "matching-edge", "kind": "line", "length": 4.0, "target_length": 1.0}
    ],
    "equal_groups": [["hole-quarter", "matching-edge"]],
    "max_segments": 100
  }
}
```

所有长度使用调用方模型单位，圆弧长度限于不超过一周。工具将尺寸下限、弦误差下限、最小段数和分段倍数协调为整数；多个相交等分组合并处理。闭圆至少三段。超过 `max_segments` 返回 incomplete，不截断后输出一个违反精度要求的可用段数。完整结果给出实际建议弦误差和可传给块计划的整数约束；尺寸来源明确标为调用方声明，尚未自动读取 CAD 曲率。

每条 `edge_segments` 只引用 `equal_group_id`，多边组成员仅在顶层 `equal_groups` 存储一次；这两个字段及 `seed_constraints` 均可分页读取。避免在每条边重复整组成员导致报告随组规模平方膨胀。

## 合批输入与输出

`ansa_mesh_sweep_prepare` 接收最多 32 个已就绪块、合计最多 200 个源 SHELL。每块提供 `id`、`shell_ids`、`direction`、`distance`、`steps` 和 `property_id`。可选 `max_penta_fraction` 为 0–1，默认 1；调用方可按工程标准设置较小值，不能把默认值当作推荐六面体比例。

同时满足以下条件才合批：方向、距离、层数和属性相同；源面合集在垂直于方向的同一平面；预计实体数量不超过现有单次扫掠预算。共享节点但参数不一致、组件超预算、悬挂源节点、非流形源边、重复源面、同坐标不同 GRID ID 或比例超限时返回 blocked，并保留问题位置。坐标舍入误差使边内部检查无法可靠分辨时也返回 blocked。完整组件按预计实体数降序打包，块重命名不改变可行性；该策略不承诺全局最少调用次数。

工具不会对近似重合的不同节点自动做合并，也不会证明尚未扫掠的目标域没有其他实体。无共享源节点的不同平面块可形成不同组；组间目标域仍要由几何计划和后续交叠检查验证。

源面悬挂节点、非流形边和精度不足检查同时接入现有扫掠执行器的写前预检；直接调用 `ansa_mesh_sweep` 也不能绕过这些检查。

`summary` 给出联合读取次数、属性预检次数、按块单独执行次数、合批后的执行次数及预计 CHEXA/CPENTA 数量。完整组参数存入证据，使用 `ansa_mesh_evidence_page(section="groups")` 读取。写工具的上下文、备份、指纹、范围保护和未知任务处理均继续生效。

## 效率记录

分别记录几何读取、分区、种子规划、源面生成、预检、扫掠、审计及保存时间，同时记录工具往返次数、读卡次数、重试和重划规模。合批能直接减少前置往返和兼容块的原生调用数量；实际耗时需在相同模型与准则下测量。

2026-10-25 的独立原生夹具包含 4 FACE、6 CONS、3 CURVE。特征冷读导出 4 次并查询 SurfaceInfo 1 次；缓存命中仍重新导出范围核验，导出降为 1 次、SurfaceInfo 为 0 次。内部计算单次约 0.0916 秒与 0.0259 秒；这些数值不含完整 MCP 往返、分页和文件保存，不外推为工业整体提速。当前自动 seed 仅覆盖已确认的显式 CURVE。

上述历史记录属于已有 `ansa_geometry_features`、种子规划和合批复用入口，不覆盖本轮 `ansa_mesh_seed_read` / `ansa_mesh_seed_apply`。新工具另有 i10、i02、i23 受限真机通过、i08 保留恢复诊断及 inch 输入拒绝的记录；该证据只覆盖上文明确列出的保存重开、hash、bounds 漂移和保护范围，不能延伸为完整正式验收、工程质量通过或连续 CAD 等价。

后续 `ansa_geometry_boundary_prepare` 固化了逐条 CONS 转换来源、备份、辅助 Part 隔离和范围审计，可减少临时自定义脚本与人工追踪 ID。其产物仍不能直接作为原始 CAD 的解析边界：2026.1.0 将圆弧转换为近似 126 样条，严格线性 112 才可在完整参数域内解析为直线，末端冗余值不一致单列。网格编排应将“原生拓扑闭合”“转换创建对应”“辅助曲线解析”“原始 CAD 几何等价”分别设门槛；缺最后一项时，保留 incomplete。下一步优先寻找保留原始边界表示的受限导出或原生曲线接口，确认圆弧精度与方向，再扩展孔环形区和筋板模板，不能将本次来源记录冒充孔识别已完成。

按原生能力优先原则复查后，转换继续调用 `ConsToCurves`，偏差检查复用 `ProjectPointToCons`，不自写投影算法。当前每条辅助曲线增加九点到原 CONS 的单向投影诊断，延长线结果按最近端点计距，保留全部采样及失败。它可揭示转换误差，不能证明连续覆盖或曲线类型。原始 FACE 导出中三维修剪边也可能为近似样条；IGES 142 的三维/参数域表示具有偏好语义，不能只取看起来更规则的一种就宣布精确。直接 CURVE 评估/长度接口在原始 CONS 探针上返回失败；Curve 包装器的局部切向/曲率虽可返回，也不作为精确解析边界依据。后续模板仍须明确工程公差和原始 CAD 验证关卡。

优先消除三类重复：同一共享面被各块分别生成；明知分段或方向不兼容仍尝试写入；每个局部预检都重新拉取全部源面卡片。已有 `mesh_source_audit` 在同时检查源/目标时也复用一次联合快照，不再额外读取源面子集。写前、备份后和写后保护用的回读继续保留。

独立复现入口为 `tests/integration/meshing_reuse_ansa.py <owned-run-dir>`；验证两个不同尺寸/层数的混合源块，检查合批后的 CHEXA/CPENTA 数量、共享竖向面、节点坐标唯一性及保存重开。它用于证明可复用原语，不能代替工业案例验收。

## 多块路线的当前落地

对于已经用显式切面形成的坐标轴对齐矩形组合，使用以下较短路线：保存原始 CAD 的完整有限域证据 → `geometry_partition_plan/apply` → `geometry_sweep_candidates` 的 T2 诊断 → `mesh_map_blocks_prepare` 的 plan/apply → `mesh_map_block_fill(volume_ids=...)` → 独立质量与保存重开。每一步都核对当前模型代次，候选不能直接授权下一步写入。

共享 FACE 在一次 MapBlock 准备中只生成一次面网格。分组填充时，工具先核验完整装配和已有实体，再对所选未填块调用一次原生 VolumesRemesh；可在同一 Part 中保留先前已经完成的块。当前外皮随已填块集合变化，最终双侧接口按实际节点 ID 和全部面片核对，不能靠最近坐标拼接。具体预算、矩形域限制及返回语义见[工具契约](structured-meshing.md#矩形多块准备与增量填充)。

2026-10-26 的独立双块原生案例，从原始 CAD 经公开切分、联合准备生成112个 CQUAD4，再分别以24+24增量或一次48个 CHEXA填充。原始域到两个结果块的间隔单元覆盖、完整 CAD 外皮、共享接口、旧块卡片保护和保存重开均通过。两策略的新 SOLID 编号顺序不同；通过显式新单元ID双射比较后，坐标、连接顺序、归属及其他卡片相同，不能称原始EID逐一相同。

同模型只读有限面域证明的实测导出次数由36降为11，内部读取约0.963秒降为0.315秒，原始快照与证明一致；合批填充原生调用由2次减为1次。两个增量填充台账阶段合计约2.125秒，合批约1.127秒。这些是当前小模型的内部阶段观测，均不含完整MCP往返或工业整件耗时，不承诺固定加速比例。

工业诊断对 i10（11 FACE）、i02（28 FACE）及 i23（42 FACE）全选面返回 T2 未支持，保留具体几何/邻接原因且不提供准备参数；冷读/缓存读前后完整快照精确一致，原STEP文件哈希不变。这个结果用于自动选择适用路线、避免错误尝试，不是工业整件网格成功案例。

## 检查点和客户端恢复

客户端库 `ansa_mcp_plugin.workflows.MapBlockJobClient` 只编排公开 MCP 工具，不在客户端调用 ANSA API。它面向已准备好的显式 `fill_groups`：逐组新鲜计划、受控填充、验证后保存独立检查点，最后执行调用者明确指定的质量准则。每次派发前写入请求、绑定和 operation ID，收到 task ID 后立即持久化；保存全部回执、台账及检查点文件SHA-256。

客户端退出后，在同一完整目标/模型绑定下调用 `resume`。它先查询原task或operation，不重发原写入；queued/running保持等待，unknown、失败、查询异常或不一致进入 `needs_attention`。它不自动打开检查点或改绑目标。后端重启、ANSA重开或模型代次变化时，必须显式重新核实并制定后续任务，不能修改旧manifest中的身份使其“继续”。检查点保存和质量通过也不能替代原始CAD覆盖或求解器验收。

完整API示例见[客户端工作流](structured-meshing.md#客户端检查点编排)。独立原生验收实际丢弃第一次成功填充回执，新建编排客户端后查询原任务并推进第二块；两个原生apply各一次、两个检查点和48个实体的明确夹具准则通过，最终检查点重开后的完整原始快照精确一致。

## 后续模板扩展的原生查证门槛

同版本官方API已确认 `VolumesMap`、`MapBlock`、`SurfaceExtrudeExtrude` 可作为孔板/环带直扫的原生候选；`FeatureHandler` 和 `CreateEntity(...,"HOLE 2D",{"contents":CONS环})` 可表达原生孔身份。特征识别和 MapBlock 均可能修改模型，不能当只读预筛。`SurfaceInfo` 的局部曲率输出没有完整柱面轴点/轴向契约，不能据此自动识别任意圆孔。

通用孔板/O-grid和任意曲面自动分块仍需独立验证。当前有限孔环直扫的验证结果如下；原生生成器负责实际网格，审计模块只证明明确输入下的有限结果。

## 有限孔环直扫

公开 `ansa_mesh_annular_source_prepare(plan/apply)` 已接通明确四块局部CAD的原生源面准备；2026-10-28收尾验收完成13个公共任务的准备→冻结→扫掠→质量→保存重开。输入与局部细化、几何预算边界见[源面准备契约](structured-meshing.md#有限孔环源面准备)，最新记录见[验收范围](../acceptance.md#2026-10-28-公开孔环准备闭环与开发范围复盘)。

2026-10-27 已在独立 ANSA 2026.1.0 上验证：明确的同轴单孔环带、平行端盖、恒截面直扫，可先将已分块 CAD 交给原生 `MapBlock` 生成面网格，选定一个完整端盖的源 SHELL，再用 `ansa_mesh_sweep(freeze_source=true)` 冻结后调用原生 `VolumesExtrude.translate`。不要求自行编写环带网格生成算法。GUI 的 Up/Fit to Target 与具体 Python 参数对应关系尚未单独验收。

工业样本 i03 的显式局部域内半径10、外半径19、直扫长度16 mm；3 mm 的面网格目标得到4个 Ready MapBlock，源面100 CQUAD4和10 CTRIA3。四层直扫生成400 CHEXA与40 CPENTA；源节点复用、全部440个源单元/层占位、500个完整外皮面片、内孔120个壁面片及外壁160个面片均独立核对。内外环最大弦误差约0.1232/0.1019 mm，小于本例0.2 mm声明值；这不是任意工程的推荐尺寸或质量标准。

源网格冻结、实体指纹及编号在保存重开后精确保持；ASPECT≤5、JACOB≥0.2的440项报告全部通过。源面多边形面积乘扫掠长度与FE总体积一致，FE体积约为解析环柱的99.8174%。这证明该多边形网格域的完整覆盖和孔洞保持；原始CAD连续域双向覆盖、未相邻单元相交专项检查、工业整件自动分解和GUI画布仍未验收。完整记录见[验收范围](../acceptance.md#2026-10-27-孔环源面冻结与原生直扫受限验收)。

### 直接填充已有四块

同一已准备模型也可用 `ansa_mesh_map_block_fill(volume_ids=[...], annular_options={...})` 直接调用原生 `VolumesRemesh`，具体输入和保护边界见[孔环填充契约](structured-meshing.md#已有孔环-mapblock-直接填充)。不重新生成面网格，不另建扫掠体，不要求各块沿统一轴形成规则源层对应。

本例单次原生填充得到512 CHEXA与98 CPENTA，共610单元；既有面网格和CAD保持，完整610个外皮面片、4组共享FACE接口及正体积回读通过。独立质量检查中5个单元超过ASPECT≤5，JACOB≥0.2全部通过；该直接填充结果的质量尚未全部合格。当前明确准则下，前述四层Freeze→Extrude案例已有全部通过的证据，不能把两条路线的质量结论混用。直接填充的公开调用链与保存重开记录另见[验收记录](../acceptance.md)。

后续对12实体闭包仅移动两个内部节点，原生SolidSmooth将5个超限减为3个；原面网格与接口保持，最大位移约0.365 mm。无进一步改善的轮次已回滚，未放宽阈值或自动重划边界。固定FACE16/20的局部面网格亦存在质量缺陷，后续划分方法按用户示范再推进，详见[局部改善记录](../acceptance.md#2026-10-28-孔环局部质量改善与固定边界限制)。

### 用户示范：清理特征线、Define Map Block、Edit Caps

2026-10-28用户在同一未网格圆环上演示：先清理多余特征线，再用原生 **Define Map Block**，最后用 **Edit Caps** 修改对应端面组。后续有限孔环开发优先按这三步组织；先检查拓扑和映射方向，再处理实际生成后的局部质量问题。不能把必要的孔边界或块间接口当作多余特征线，也不按坐标近似合并节点。

在用户操作的教学窗口（PID4480）只读回读并保存画布：FACE由28减到22，CONS由54减到38，HOT POINT由30减到20；得到4个Map Block及1732个面单元（1724 CQUAD4、8 CTRIA3）。四个块均为 `Ready to Mesh / Unmeshed`，SOLID数为0；这是原生定义、面网格和caps设置的示范，尚不是实体填充及质量验收。

本例四块统一采用外圆柱面组为master、内圆柱面组为slave，环形端面及径向分界面为round侧面。`mesh.GetMapVolumeBoundaries`的实际回读为：

| VOLUME | master外壁FACE | slave内壁FACE | round侧面FACE |
| --- | --- | --- | --- |
| 1 | 13 | 21 | 11、19、23、24 |
| 2 | 1 | 9 | 11、17、22、25 |
| 3 | 2 | 7 | 6、10、22、27 |
| 4 | 14、26 | 20、29 | 4、10、23、28 |

第4块端面仍由多个FACE组成；caps应按完整对应面组理解，不应强制每端只有一个FACE。前后实体清单和原生分组表明用户完成了拓扑清理与映射方向调整；仅凭最终状态不能反推每一次GUI点击的顺序，操作顺序按用户说明记录。当前 `GetVolumesMapParameters` 对这些Map Block返回None，不据此推断层数或零步数。

观察证据位于 `runtime/verification/annular-user-method-0187d5c434ee47beb19c2238a20a4b2e/` 的 `report.json`、`model-readback.json` 和 `user-annular-canvas.png`。回读前后计数一致；没有保存、重开、修改或填充用户模型，窗口保持打开。

同版本独立副本已确认 `mesh.DefineCaps(volume, Cap1, Cap2)` 可修改对应面组，成功返回None；必须用 `GetMapVolumeBoundaries` 回读，不能把None当失败，也不能把自动MapBlock分组当作显式caps编辑。该函数未收录于当前本机官方autocomplete stub，准确合同来自2026.1.0主线程探针。专用 `ansa_mesh_map_block_caps(plan/apply)` 已接入，并通过1732面单元副本的真实MCP修改、范围保护及保存重开。孔环填充分支现为2000边界SHELL、每端400线性SHELL的有界范围；拓扑清理和任意重划仍不等同于已有通用专用工具。

### 通用原生划分顺序

用户进一步明确：大部分复杂实体划分先切分几何，再用 **Define Map Block** 初划。若面网格不理想，用 **Surface Mesh** 工具重划相应面，再 **Freeze** 已经调整好的面网格；期间可按实际几何调整caps映射组，最后生成实体网格。

Freeze的时机是所选面及关联接口两侧的流向、分段和层数协调后，保护范围应明确到面/网格及共享CONS；单侧网格质量通过不表示两侧都能使用。需要改变已有接口时，按[关联块组执行规则](#关联块组执行规则)重新规划受影响范围。caps可以是复合面组，对应方向由具体几何决定。本例圆环采用外壁→内壁，带孔板可采用厚度方向底面→顶面。优先改善切分、面网格和caps，实体生成后的平滑只处理剩余局部问题。

专用MCP支持范围以实际schema为准；目前Surface Mesh已有网格的重划与独立Freeze组合尚未形成通用专用入口。原生功能存在、通过MCP脚本调用、专用工具实现及案例验收须分别说明，不将这条通用方法解释为任意工业几何已自动网格化。

### 固化中心单孔矩形板

用户确认的细化孔板方法现有[参数化原生流程](plate-hole-workflow.md)和[示例参数](../../examples/meshing/plate-hole-o-grid.json)：中心环带＋外围矩形共20块，以相容整数分段调用原生四边映射，Freeze后设厚度方向caps并填充。客户端 `plate_hole_script` 经既有MCP脚本入口调用；当前限定原始轴对齐矩形中心孔恒厚CAD，不是任意已有面网格重划/Freeze的通用专用工具，也不改变MCP工具数量。实际源码链路与工业下一步状态见[验收范围](../acceptance.md)。
