# 控制面板布局调整

本页记录已实施的布局方案。依据为用户于 2026-10-20 提供的面板截图；本轮已在独立 ANSA 2026.1.0 窗口验证，具体范围见下文。

## 当前问题

- 本实例与 AI 当前目标相同时，两组进程、模型和授权信息重复。
- 完整实例、会话、后端 ID 以及启动标识、代次属于排障信息，初学者难以判断下一步操作。
- 模型路径与技术说明组合成长行，截图已出现横向滚动，关键状态难以同时读到。
- “已授权”和“受控写入待后端确认”并排出现，没有解释连接授权与执行前校验的不同用途。

## 信息层次

概览只回答三个问题：是否连通、AI 要操作哪个模型、接下来做什么。

| 信息 | 概览呈现 | 诊断页保留 |
| --- | --- | --- |
| 连接与任务 | 等待后端／读取模型／待连接／已连接／已暂停，附下一步操作 | 原始状态、错误、读取时间 |
| AI 操作目标 | 本窗口；其他窗口时显示模型名并提示核对 | 完整进程、实例、会话、后端 ID |
| 当前模型 | 文件名、求解器名称、最近读取时间 | 模型完整路径、代次、检测方式 |
| 写入状态 | 执行任务前自动校验；确有拒绝时说明原因 | 写入门禁和范围的完整结果 |
| 技术标识 | 默认隐藏；同名模型必要时用 PID 辅助辨认 | PID、启动标识、各类 ID 和代次 |

本窗口就是 AI 目标时，只显示一次模型信息，用“AI 当前操作此窗口”说明关系。只有目标不同时才增加目标模型摘要，避免误操作。诊断详情必须保留且便于复制，不能通过隐藏信息削弱目标身份核对。

优先复用现有概览、诊断日志和设置页签，不增加新页面。状态同时使用明确文字，不能仅依赖颜色；长路径换行，不靠缩小字体容纳。底层身份校验继续使用完整标识。

## 实施与验收

1. 概览使用分组标签布局，保留当前模型、求解器、AI 操作目标、任务状态和读取时间；同窗口不再重复展示。
2. 完整技术身份和模型路径移到诊断页，增加“查看诊断详情”入口；三个主按钮统一为“连接此窗口”“暂停任务”“恢复任务”。
3. 通过单元覆盖离线、读取中、等待响应、已绑定、暂停、旧快照、重连及目标为其他窗口的状态；缓存不能代替执行前校验。
4. 独立真机验证自动读取但未授权、连接、暂停、恢复、诊断切换及常规／紧凑窗口。当前显示缩放为 200%，窗口边界分别为 1026×791 和 862×787；诊断长行按窗口换行。

真机按钮检查通过官方 `BCButtonRunClickFunction` 调用生产回调，未验证物理鼠标、键盘遍历、屏幕阅读器及其他 DPI。没有运行建模、保存或删除模型的 API。源码回归和模拟 MCP 结果见[验证范围](../acceptance.md)。

## 资料

- [Microsoft：User Interface Text](https://learn.microsoft.com/en-us/windows/win32/uxguide/text-ui)：减少重复、便于扫读、先呈现必要信息。该文属于早期 Windows 指南，本方案采用其文字组织原则，不照搬旧视觉样式。
- [Nielsen Norman Group：10 Usability Heuristics](https://www.nngroup.com/articles/ten-usability-heuristics/)：清楚反馈系统状态、使用用户语言、突出与任务相关的信息。
